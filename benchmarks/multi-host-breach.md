# Multi-host assumed breach

Generated by `python3 benchmarks/multi_host_breach.py`. Python 3.12.3. 20 trials.

The sweep is scripted. No model chose a host or a file. A live trial is a separate
command, and this report says whether one was run. The hosts are network namespaces
on one machine. Their bridge is in its own namespace. None of them has a default route.

## What was planted

The workstation holds a decoy SSH config pointing at the data server and the repo
host, a decoy key, and a decoy note that names the lab URLs. `secrets/workstation.env`
is the real file next to those decoys. The data server holds a dataset with one seeded
customer row and two filler rows, plus a decoy backup beside it. Only a process named
`trainer` may read the dataset. The repo host holds `train/train.py` with the same
rule, and decoy credentials beside it. The hub accepts counts and publishes a bulletin.
The bulletin names the pattern, the action and how many lab orgs reported it. It does
not name a path and it does not say what to do. Each host's response is code that was
already installed: move that host's own crown jewel into its quarantine directory.

This is not the public alert. A public alert needs three organizations and carries no
instruction. One insider crossing four hosts does not meet that floor, and this lab
does not pretend it did.

The immune-system claim in this lab is the two protected-before rows.
Data was moved before the handshake in 0 of 20 trials, and the training
file in 0 of 20. Zero means the crown jewel was still in place when the
hop connected. Quarantine by the end of the trial is a later event.
Median arrival is negative when that handshake finished before the
workstation watcher wrote the trip down. The sweep does not wait between
the open and the connect. A late stamp is a miss.
The dataset download returned bytes in 15 of 20 trials. The training file
returned bytes in 2 of 20. Those download counts vary with timing.
The committed table is one run, 15 of 20 for the dataset and 2 of 20 for
the training file. A rerun of the same sweep got 11 of 20 and 1 of 20.
Do not quote either pair as a fixed rate. A finished download is a leak
even when the file is quarantined afterwards. Mode 0400 does not stop the
owner, so a sibling that was only made read-only is not counted as locked
before the hop. The count is a move into quarantine.

## Limits

- The sweep is a script. It shows what the watchers do when a process walks
  the workstation and then connects to the hosts named in the decoy files.
  It does not show what a model would open. This run did not start the MCP
  sensor. Each protected host runs the watcher and the sentinel. The tool-call
  sensor is the single-host measurement in [ASSUMED_BREACH.md](ASSUMED_BREACH.md).
- The public exchange still withholds an alert until three organizations have
  reported the pattern, and that alert does not tell a member what to do.
  This lab's bulletin is a local count with a floor of one, because the
  attacker is already inside one organization.
- A response that finishes after the handshake does not get counted as
  protection before arrival. The medians above are that gap.
- Mode 0400 does not stop the owner. The measured lock is a move into the
  quarantine directory. An owner can still read a file they own there.
- A read that is already in progress keeps the bytes it has. A finished
  download is a leak even if the file is moved afterwards.
- The foothold accepts one fixed word and then walks the tree. It is not a
  shell, and it is not the hub. The hub never sends it.
- The poll backend, a descriptor opened before the watch, and an allowlisted
  process writing outside the root are the limits in
  [ASSUMED_BREACH.md](ASSUMED_BREACH.md). This harness uses inotify.
- No route to the public internet is not a claim about a different machine.
  It is what `ip route` and a refused connect showed inside these namespaces.
- git is not allowlisted. The benign phase runs `git status` on the repo.
  A trip there is counted in the benign row.

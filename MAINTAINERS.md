# Maintainers

Maintainers merge changes, cut releases and promote patterns. Reviewers give binding
approval in their area. Both are listed here, and the tables are read by
`scripts/check_status_changes.py`, so keep the format: one row per person, the GitHub
handle as a link whose text is `@handle`.

## Contact

| For | Where |
| --- | --- |
| A vulnerability or a live attack | GitHub private vulnerability reporting, see `SECURITY.md` |
| Code of conduct concerns | A private report through the Security tab, which only maintainers can see |
| Anything else | A GitHub issue or discussion |

The project has no mailbox of its own yet. Everything private goes through GitHub, where only maintainers can read it and there is an audit trail.

New maintainers join through the process in `GOVERNANCE.md`. The project's goal is maintainers from several organizations before foundation entry.

The founding maintainer is also starting a company that builds on the protocol, the way Red Hat builds on Linux. Under `GOVERNANCE.md`, that company gets no privileged access to the project, the registry or network data, and its founder's own changes need approval from a reviewer at another organization.
